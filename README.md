# 한국 관세청 수출입 데이터 대시보드

관세청 품목별·국가별 API로 데이터를 수집하고 CSV를 GitHub Pages에서 표시합니다.

## 실행

- `All Export Data`: 매월 15일 01:00 UTC, 즉 한국시간 오전 10시. 수동 실행도 가능합니다.
- `Customs Export Data`, `Country API Test`: 개별 점검용 수동 실행만 제공합니다.
- 세 워크플로는 같은 concurrency 그룹을 사용하므로 서로 동시에 실행되지 않습니다.
- GitHub 저장소의 Actions secret `CUSTOMS_API_KEY`를 사용합니다. 키를 코드에 넣지 마세요.

```bash
python -m pip install requests
python -m unittest discover -s tests -v
python test.py
python country_test.py
```

두 수집 파일은 **`customs_common.py`와 함께** 교체해야 합니다. 워크플로의 검증 단계는 `tests/`도 필요합니다. `hs_codes.csv`는 기존 파일을 그대로 사용합니다. 품목명의 쉼표는 큰따옴표로 감싸는 표준 CSV 형식을 권장하며, 현재 파일의 따옴표 없는 `GDDR기판, FPCB`도 전체 이름으로 읽습니다.

## 호출과 재시도

- 최근 3개월과 기존 데이터의 누락월만 조회합니다. 과거 데이터가 없는 품목은 2020년부터 수집합니다.
- 기존 데이터가 있는 품목을 먼저 처리하고, 기간은 연도를 넘지 않도록 나눕니다.
- 요청 간격 기본값은 3초, 연결/응답 타임아웃은 15초/60초입니다.
- HTTP 429·일시적 서버 오류·네트워크 오류는 최대 3회까지 시도합니다. 30초, 60초에 무작위 지연을 더하고 `Retry-After`가 더 길면 그 시간을 적용합니다.
- `Retry-After`가 300초를 초과하거나 재시도가 모두 실패하면 해당 수집 실행의 추가 호출을 중단합니다. 일일 할당량·인증 오류도 추가 호출을 중단합니다.
- 서버 오류나 빈 기간 응답이 나오면 전체 기간을 월별로 다시 호출하지 않습니다. 정상 기간 응답에 일부 월만 빠진 경우에 한해 누락월만 한 번씩 별도 조회합니다. 각 조회의 일시적 오류 재시도 상한은 동일합니다.
- API가 `totalCount`를 제공하면 페이지 전체를 수집하고 행 수와 중복을 검증합니다. 페이지가 누락되거나 반복되면 그 구간을 저장하지 않습니다.
- 실행당 호출 상한은 수집기별 200회입니다. 최초 36개 품목의 과거 데이터 수집은 여러 번 실행해야 할 수 있습니다. `CUSTOMS_MAX_REQUESTS`와 `CUSTOMS_REQUEST_INTERVAL`로 조정할 수 있습니다.

## 데이터 보존

- HTTP 200이어도 XML 정상 결과 코드를 확인합니다. 필수 수치, 월, HS코드, 중복 행을 검증합니다.
- 빈 응답과 누락된 월은 0으로 변환하지 않습니다. 명시적인 월·품목 행에 금액 0이 들어온 경우에는 유효한 수치로 처리합니다.
- 일반 수집은 검증된 응답의 월만 교체하고 기존 다른 월은 유지합니다.
- 국가별 수집은 해당 월의 8개국 응답이 모두 있어야 갱신합니다. `기타 = 전체 − 주요 8개국`의 금액과 중량이 모두 음수가 아닌지 확인합니다.
- 통합 실행에서는 일반 수집에서 이번에 갱신한 월을 `.customs_refreshed.csv`로 전달합니다. 국가별 수집은 그 월의 최신 전체 합계만 사용합니다. 이 임시 파일은 Git에 저장하지 않습니다.
- 개별 `Country API Test` 실행은 기존 `summary_<HS>.csv`를 사용하므로 일반 수집이 먼저 정상 갱신되었는지 확인해야 합니다.
- 완성한 CSV를 임시 파일에 기록한 뒤 원자적으로 교체합니다. 해당 품목의 API 응답이 모두 실패하면 기존 상세·요약 파일을 다시 쓰지 않습니다. 유효 응답이 전혀 없는 실행에서는 통합·최신 CSV도 유지합니다.
- 기존 통합 파일에만 남아 있는 과거 행도 통합 파일 재생성 과정에서 보존합니다.
- 실제 무거래와 API 누락을 명확히 구분할 수 없는 빈 응답은 보류합니다. 따라서 이력이 없는 HS코드나 거래가 적은 국가에서는 계속 미완료로 표시될 수 있습니다. 이때 임의로 0을 채우지 말고 관세청 원자료를 확인해야 합니다.

## 실패 표시와 결과 확인

- `export_failed.csv`, `country_failed.csv`에 품목·국가·기간별 오류가 기록됩니다.
- 일반 수집 종료 코드: `0` 완료, `1` 일부 구간 미완료, `2` 호출 중단/인증키 없음. 국가별 수집은 완료 `0`, 미완료 `1`입니다.
- 통합 실행에서 일반 수집 종료 코드가 `2`이면 국가 API도 호출하지 않습니다. `1`이면 이번에 갱신된 전체 합계가 있는 월만 국가별로 진행합니다.
- 워크플로는 성공적으로 검증한 CSV와 오류 기록을 저장한 뒤, 수집 미완료가 있으면 실패 상태로 표시합니다. 일부 오류가 있었는데 전체 성공으로 표시되는 일을 방지합니다.
- CSV는 실행 결과 artifact로도 30일간 보관됩니다. Git push 충돌은 강제 덮어쓰지 않고 실패로 남깁니다.
- API 예외에서 인증키가 포함될 수 있는 URL/원문 메시지를 출력하지 않습니다.

## 검증 범위

`tests/test_collectors.py`는 실제 API나 인증키를 사용하지 않고 429, Timeout, Retry-After, XML 오류, 페이지 분할, 누락월, 기존 파일 보존, 국가별 합계 검증을 재현합니다.

`tests/test_repository_compatibility.py`는 저장소의 기존 CSV를 임시 디렉터리에 복사하여 실패 시 바이트 단위 보존과 실제 CSV 열 호환성을 검증합니다. 원본 CSV를 수정하지 않습니다. PR의 `Collector Regression Tests` 워크플로는 인증키 없이 이 테스트만 실행합니다.

실제 API의 기간조회 지원과 응답 형식, 현재 할당량 상태는 인증된 Actions 실행으로 별도 확인해야 합니다. 테스트 통과가 실제 관세청 응답 성공을 뜻하지는 않습니다.

대시보드는 `index.html`에서 `summary_all.csv`와 `country_all.csv`를 읽습니다. API 수집이 정상화된 후 실제 게시 페이지에서 최신월과 국가별 합계를 확인합니다. 현재 서로 다른 두 HS코드의 품목명이 `PCB`로 같고 대시보드는 품목명으로 구분하므로, 두 코드의 데이터가 모두 추가되기 전에 HS코드 기준 구분도 점검해야 합니다. 이번 수집 안정화 수정에서는 대시보드 표시 방식을 변경하지 않았습니다.
